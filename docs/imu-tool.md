# IMU 台架工具使用指南

`tools/imu.py` 用一条命令完成：烧录 → 回读校验 → 跑健康测试 → **告诉你哪一路坏了、下一步查哪根线**。

不需要记 `idf.py` 的参数，也不需要自己翻日志判断。

## 一、第一次用

每开一个新终端，先让 ESP-IDF 可用：

```bash
. ~/.espressif/v6.0.2/esp-idf/export.sh
```

然后把板子插上，确认电脑能看见它：

```bash
ls /dev/serial/by-id/
# 应该看到 usb-Espressif_USB_JTAG_serial_debug_unit_..._if00
```

## 二、三种用法

### 1. 直接跑一个阶段

```bash
python3 tools/imu.py run 6
```

`2` / `6` / `11` 分别对应：

| 阶段 | 应该接的源 |
|---|---|
| `2` | sid 0, 1 |
| `6` | sid 0, 1, 2, 3, 4, 7 |
| `11` | sid 0 到 10 |

改动线就重跑同一条命令，**不要**为了让它通过去降 SPI 频率或改阈值。

### 2. 交互模式（不知道敲什么时用这个）

```bash
python3 tools/imu.py
```

进入后是这样的提示符，直接输入命令：

```
imu> run 6
imu> help
imu> quit
```

一进来会先打印当前状态（串口找没找到、镜像是哪个），并按顺序告诉你第一次该做什么。
跑完一次后如果想保留原始输出：

```
imu> run 6 /tmp/今天这次.raw
```

### 3. 离线看一份结果（不接板子）

```bash
python3 tools/imu.py analyze /tmp/今天这次.raw 6
```

最后那个 `6` 是这份结果对应的阶段；不写就按全部 11 路判断。
这条命令也能在没插板子的电脑上跑，用来对比两次改线前后的差别。

## 三、输出怎么读

先是一张表：

```
src  状态           自检    WHO  总线  CS
  0  PASS     34/34   0x70   B   1
  1  ABSENT    0/0    0x00   A   2
```

- `PASS` —— 这一路完全正常
- `ABSENT` —— 这个位置没找到器件
- `FAIL` —— 找到了，但某项检查没通过
- `自检` —— 通过项/总项数
- `WHO` —— 芯片身份，正常是 `0x70`

表下面是**判断与下一步**，每一行都写明该用万用表查哪根线，从上往下查就行：

```
  src 2  稳定读回 0x00：门是使能着的、输出也已经接到总线上，被拉低的是输入端
          → 模块 sid2 SDO → U1 p9
          → 模块 sid2 VCC 是否有 3.3 V
```

## 四、几种常见读数代表什么

| 现象 | 含义 | 先查什么 |
|---|---|---|
| 稳定读回 `0x00` | 门已使能、输出也到总线了，**输入端**被拉低 | 模块 SDO 到门脚；模块有没有 3.3 V |
| 读回 `0xFF` | 这一路**没人驱动总线**，门没导通 | CS 到门的 `/OE` 脚 |
| `FAIL` 且提示「burst 数据损坏」 | 12 字节传完了但数据坏 | 该通道接触不良，重插那几根线 |
| `FAIL` 且提示「STATUS 传输失败」 | 连单字节都传不动 | SPI 线与 CS 的接触 |
| 全部 `PASS` | 这一阶段通过 | —— |

## 五、不想接硬件时的自检

```bash
python3 tools/imu.py audit
```

会跑一遍工具自己的离线测试，确认诊断规则和文件解析没被改坏。正常只输出一行，最后那个数字是当前测试项数：

```
离线测试 73 项，失败 0 项
```

## 六、常见问题

**提示「没有找到 Espressif 串口」**
板子没插好，或者 USB 线只能充电不传数据。换一根数据线，再用 `ls /dev/serial/by-id/` 确认。

**停在「烧录并运行健康测试，约 20 秒…」不动**
正常，烧录本来就要二十秒左右。

**提示 `idf.py not found`**
忘了第一步的 `export.sh`。

**跑完显示「捕获里没有 MATRIX_DONE」**
烧录或复位中途断了，重跑一次。

**想看两次结果的差别**
两次都用 `run 6 文件名` 保存，然后分别 `analyze` 打开对比。

## 七、它不做什么

- 不改 SPI 频率、不改判定阈值 —— 失败就是失败
- 不保留原始日志（除非你用 `run 6 文件名` 明确要求）
- 不做 TUI / 图形界面；现在只有命令行
